## 阿里云控制台配置

### 1. 创建AccessKey

**步骤**:

1. 登录阿里云控制台
2. 进入 **访问控制 (RAM)** → **用户管理**
3. 创建子账号或使用主账号
4. 点击 **创建AccessKey**
5. **重要**: 立即保存 AccessKey ID 和 AccessKey Secret（只显示一次）

**安全建议**:
- ✅ 使用RAM子账号，只授予短信服务权限
- ✅ 定期轮换AccessKey
- ❌ 不要将AccessKey提交到代码仓库

**权限策略**:
```json
{
  "Version": "1",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": "dysms:*",
      "Resource": "*"
    }
  ]
}
```

---

### 2. 创建短信签名

**步骤**:

1. 进入 **短信服务控制台** → **国内消息** → **签名管理**
2. 点击 **添加签名**
3. 填写签名信息：
   - **签名名称**: `台风创意文化`
   - **签名来源**: 企事业单位的全称或简称
   - **适用场景**: 验证码
4. 上传证明文件（营业执照等）
5. 提交审核（通常2小时内审核完成）

**注意事项**:
- 签名长度：2-12个字符
- 签名必须与公司资质匹配
- 验证码场景建议使用公司简称

---

### 3. 创建短信模板

**登录模板**:
- **模板CODE**: `SMS_500655304`
- **模板类型**: 验证码
- **模板内容**: `登录验证，您的验证码为 ${code}`
- **申请说明**: 用于代理商登录验证

**注册模板**:
- **模板CODE**: `SMS_500535284`
- **模板类型**: 验证码
- **模板内容**: `注册账号验证码为：${code}`
- **申请说明**: 用于新代理商注册验证

**模板规范**:
- 必须包含变量 `${code}`
- 验证码模板不得包含营销内容
- 模板长度：≤500字符
- 审核时间：通常2小时内

**步骤**:

1. 进入 **短信服务控制台** → **国内消息** → **模板管理**
2. 点击 **添加模板**
3. 填写模板内容
4. 提交审核

## 服务器环境配置

### 1. 环境变量配置

**文件位置**: `/root/projects/test111/server/.env`

**配置项**:
```bash
# 短信服务开关
SMS_ENABLED="true"

# 阿里云AccessKey（生产环境）
SMS_ACCESS_KEY_ID="你的AccessKey ID"
SMS_ACCESS_KEY_SECRET="你的AccessKey Secret"

# 短信签名
SMS_SIGN_NAME="台风创意文化"

# 短信模板CODE
SMS_TEMPLATE_CODE_LOGIN="SMS_500655304"
SMS_TEMPLATE_CODE_REGISTER="SMS_500535284"
```

**配置说明**:
- `SMS_ENABLED`: 控制短信服务启用/禁用
- 开发环境可设置为 `"false"` 使用模拟验证码
- 生产环境必须设置为 `"true"` 启用真实短信

**关键功能**:
- ✅ 多模板支持（LOGIN/REGISTER）

## 常见问题

### Q1: 短信发送失败，提示"签名不存在"
**原因**: 签名未审核通过或签名名称配置错误
**解决**:
```bash
# 1. 检查签名配置
grep SMS_SIGN_NAME /root/projects/test111/server/.env

# 2. 登录阿里云控制台检查签名状态
# 3. 确保签名状态为"审核通过"
```

---

### Q2: 短信发送失败，提示"模板不存在"
**原因**: 模板CODE配置错误或模板未审核通过
**解决**:
```bash
# 检查模板配置
grep SMS_TEMPLATE_CODE /root/projects/test111/server/.env

# 确认模板CODE与阿里云控制台一致
# 登录模板: SMS_500655304
# 注册模板: SMS_500535284
```

---

### Q3: 短信可以发送，但收不到
**原因**: 手机号被运营商拦截或手机设置问题
**解决**:
1. 检查手机短信拦截设置
2. 尝试其他手机号测试
3. 查看阿里云控制台"发送记录"，确认发送状态
4. 联系运营商客服解除拦截

---

### Q4: 频繁收到"触发60秒限流"错误
**原因**: 用户在60秒内多次点击获取验证码
**解决**: 这是正常的防刷机制，属于预期行为

---

### Q5: 提示"今日发送次数已达上限"
**原因**: 同一手机号当日发送超过10条
**解决**:
- 正常情况：等待次日重置
- 异常情况：检查是否存在恶意刷短信
- 可在代码中调整限额（不建议超过20条/日）

---

### Q6: AccessKey失效或泄露怎么办？
**解决**:
1. 立即登录阿里云控制台禁用旧AccessKey
2. 创建新AccessKey
3. 更新服务器 .env 配置
4. 重启服务: `pm2 restart firework-api`

---

### Q7: 短信成本过高怎么优化？
**优化建议**:
1. 购买短信套餐包（单价更低）
2. 启用图形验证码，防止机器人刷短信
3. 增加发送间隔（从60秒改为120秒）
4. 限制每日每手机号发送次数（当前10条）
5. 对频繁发送的IP进行风控

---

### Q8: 如何临时关闭短信服务（测试环境）？
**解决**:
```bash
# 编辑 .env 文件
vi /root/projects/test111/server/.env

# 修改配置
SMS_ENABLED="false"

# 重启服务
pm2 restart firework-api
```

关闭后系统会使用模拟验证码 `123456`

---

### Q9: 验证码收到了，但提示"验证码错误"
**原因**: 验证码过期（5分钟）或输入错误
**解决**:
1. 检查验证码是否在5分钟内
2. 确认输入的验证码与短信完全一致
3. 重新获取新验证码

---

### Q10: 部署到新服务器后短信发不出
**检查清单**:
```bash
# 1. 检查 .env 文件是否存在
ls -la /root/projects/test111/server/.env

node tools/check-sms-config.js

# 3. 检查服务器出网是否正常
curl -I https://dysmsapi.aliyuncs.com

# 4. 检查PM2服务状态
pm2 status
pm2 logs firework-api --lines 50
```

---

### 2. 月度成本估算

**假设**:
- 活跃代理商: 100人
- 平均每人每月登录: 20次
- 新增注册: 10人/月

**计算**:
```
登录验证码: 100人 × 20次 = 2000条
注册验证码: 10人 × 2次（注册+登录） = 20条
月度总量: 2020条
月度成本: 2020条 × ¥0.036 = ¥72.72
```

**年度成本**: 约 ¥872

---

### 3. 成本优化建议

1. **购买套餐包**: 比按量付费节省20%
2. **限制发送频率**: 60秒间隔 + 10条/日上限
3. **验证码复用**: 5分钟内验证码有效期复用
4. **图形验证码**: 防止机器人恶意刷短信
5. **监控异常**: 及时发现恶意刷短信行为
