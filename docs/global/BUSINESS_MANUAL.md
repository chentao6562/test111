## 一、产品概述

### 1.1 业务模式

**核心理念**: 线上免费预约 + 到店全款付款

- 线上只做信息预约，不收取任何费用
- 真正的交易（付款、发货）全部在线下门店完成
- 预约有礼：阶梯赠品激励机制
- 门店30分钟内电话确认，提升服务体验

## 二、用户角色体系

### 2.1 角色定义

| 角色 | 说明 | 使用端 | 权限范围 |
|------|------|--------|---------|
| 普通客户 | 最终消费者 | H5客户端 | 浏览商品、提交预约、查看预约 |
| 门店老板 | 货主，拥有商品和门店 | 线下 | 线下收款，不参与系统分润 |
| 总代理（蒙庆） | 帮门店运营分销系统 | 管理后台 | 系统最高权限，设置成本价和供货价 |
| 一级推销员 | 向总代理拿货 | H5推销员端 | 设置零售价、给二级的价、发展二级 |
| 二级推销员 | 向一级推销员拿货 | H5推销员端 | 只能设置零售价 |
| 门店员工 | 门店的工作人员 | 门店端H5 | 预约确认、提货核销、库存管理 |
| 管理员 | 后台管理人员 | 管理后台 | 系统配置、数据分析、人员管理 |

### 2.2 层级体系

```
门店老板（货主，线下收款，不参与系统分润）
    ↓ 委托运营
总代理/蒙庆 (isMaster=true)  ← 系统运营方
    ├── 一级推销员 (type='LEVEL1')
    │       ├── 二级推销员 (type='LEVEL2')
    │       └── 二级推销员 (type='LEVEL2')
    └── 一级推销员 (type='LEVEL1')
            └── ...
```

### 2.3 推销员激活规则

- 新注册推销员默认未激活
- 累计成交金额达到激活门槛后激活
- 激活后才能正常结算利润

## 三、价格体系

### 3.1 四级价格结构

```
成本价(costPrice)           ← 总代理从门店的进货成本
    ↓
供货价(supplyPrice)         ← 总代理给一级推销员的拿货价
    ↓
一级给二级的价(subPrice)    ← 一级给二级的拿货价
    ↓
零售价(retailPrice)         ← 客户实际支付价格（门店收取）
```

### 3.2 定价权限

| 推销员类型 | 可设置价格 | 限制条件 |
|-----------|-----------|---------|
| 总代理 | 成本价、供货价、建议零售价 | 无限制 |
| 一级推销员 | 零售价、给二级的价(subPrice) | 零售价 ≥ 供货价；subPrice ≥ 供货价 且 subPrice ≤ 零售价 |
| 二级推销员 | 零售价 | 零售价 ≥ 一级给的价(subPrice) |

### 3.3 价格校验规则

```javascript
// 一级推销员设置价格
if (retailPrice < supplyPrice) throw "零售价不能低于供货价"
if (subPrice < supplyPrice) throw "给二级的价不能低于供货价"
if (subPrice > retailPrice) throw "给二级的价不能高于零售价"

// 二级推销员设置价格
if (retailPrice < subPrice) throw "零售价不能低于一级给的价"
```

### 3.4 利润分配规则

| 订单来源 | 总代理利润 | 一级利润 | 二级利润 |
|---------|-----------|---------|---------|
| 总代理直销 | 零售价 - 成本价 | 0 | 0 |
| 一级推销员 | 供货价 - 成本价 | 零售价 - 供货价 | 0 |
| 二级推销员 | 供货价 - 成本价 | subPrice - 供货价 | 零售价 - subPrice |

### 3.5 利润计算示例

**商品定价**：
- 成本价：50元
- 供货价：60元
- 一级给二级价：70元
- 零售价：100元

**二级推销员成交100元订单**：
- 总代理利润：60 - 50 = 10元
- 一级利润：70 - 60 = 10元
- 二级利润：100 - 70 = 30元
- 门店收取：100元

## 四、预约全流程

### 4.1 客户预约流程

```
① 客户访问推销员链接
② 浏览商品（显示推销员定价）
③ 选择商品加入采购单
④ 填写预约信息（姓名、电话、提货日期）
⑤ 提交预约【免费，无需支付】
⑥ 等待门店电话确认
```

### 4.2 门店确认流程

```
① 收到新预约通知
② 30分钟内拨打客户电话
③ 确认预约信息（商品、数量、提货日期）
④ 记录通话结果
   - 接通确认 → 预约成功
   - 3次未接通 → 确认失败
⑤ 系统自动更新预约状态
```

### 4.3 备货与核销流程

```
① 提货前一天系统自动转为待备货
② 门店员工准备商品
③ 生成提货码（二维码或数字码）
④ 客户到店出示提货码
⑤ 员工扫码核销
⑥ 客户付全款 + 领商品 + 领赠品
⑦ 利润即时结算到推销员余额
```

### 4.4 预约状态流转

```
待确认(0) → 确认中(1) → 已确认(2) → 待备货(7) → 备货中(8) → 待提货(9) → 已完成(3)
               ├─→ 确认失败(6) [3次未接通]
               └─→ 已取消(4) [客户取消]
                         └─→ 已过期(5) [3天未到店]
```

| 状态值 | 状态名 | 说明 | 下一步 |
|-------|-------|------|--------|
| 0 | 待确认 | 新预约，等待门店电话确认 | 门店拨打电话 |
| 1 | 确认中 | 门店正在联系客户 | 等待接通 |
| 2 | 已确认 | 电话确认成功 | 等待提货日期 |
| 7 | 待备货 | 提货前一天，系统提醒备货 | 门店准备商品 |
| 8 | 备货中 | 门店正在备货 | 完成备货 |
| 9 | 待提货 | 备货完成，等待客户提货 | 客户到店 |
| 3 | 已完成 | 到店付款提货完成 | 利润结算 |
| 4 | 已取消 | 客户主动取消 | 无 |
| 5 | 已过期 | 确认后3天未到店 | 计入爽约 |
| 6 | 确认失败 | 3次电话未接通 | 无 |

| ≥ ¥1000 | 超级棒棒糖1个 | ¥10 |

### 5.2 赠品成本扣除

赠品成本从推销员利润中扣除：
1. 首先从二级推销员利润扣除
2. 二级利润不足，从一级推销员利润补充扣除
3. 一级利润不足，从总代理利润补充扣除

### 5.3 赠品发放流程

1. 核销时系统根据预约金额匹配赠品档位
2. 显示应发赠品清单
3. 员工实际发放赠品
4. 确认发放完成

|------|---------|---------|---------|

- 系统自动标记为"已过期"
- 计入客户爽约记录
- 自动提升风控等级

- 爽约3次自动加入黑名单
- 黑名单客户无法提交新预约
- 管理员可手动解除黑名单

## 九、财务管理

### 9.1 推销员提现

**流程**：
1. 推销员申请提现（最低100元）
2. 余额立即扣减
3. 管理员审核
   - 通过：进入待打款
   - 拒绝：余额退回
4. 确认打款完成

### 9.2 利润结算时机

- **即时结算**：核销完成时立即入账到推销员余额
- 不再有T+1延迟结算

### 9.3 余额负数处理

- 代金券核销允许余额变为负数
- 下次利润结算时先补齐负余额
- 剩余部分再入账

## 十一、常见问题FAQ

### Q1: 客户预约后可以修改吗？

A: 待确认状态可以取消重新预约；已确认后联系门店修改。

### Q2: 推销员如何查看自己的利润？

A: H5推销员端 → 我的 → 分润中心

### Q3: 代金券可以给别人用吗？

A: 不可以，代金券只能推销员本人在门店使用。

### Q4: 客户爽约后还能预约吗？

A: 2次爽约内可以预约但无赠品；3次及以上进入黑名单，无法预约。

### Q5: 砍价没砍到底价可以下单吗？

A: 可以，按当前已砍到的价格下单。

### Q6: 拼团失败怎么办？

A: 拼团过期后各成员的预约仍然有效，只是无法获得拼团赠品。

### Q7: 转盘碎片会过期吗？

A: 会，默认7天过期。需要在过期前兑换。

### Q8: 余额变成负数怎么办？

A: 正常情况，下次有利润结算时会自动补齐。
