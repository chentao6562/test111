## 二、发现并修复的BUG

### BUG-1: 秒杀商品核销时错误扣减主库存 (P0)

| 属性 | 值 |
|------|-----|
| 严重度 | P0 (严重) |
| 状态 | **已修复并验证** |
| 影响范围 | 所有秒杀商品 |

**问题描述**:
- 秒杀商品使用独立库存 `flash_sale_items.flash_stock`
- 创建预约时通过 `flashSaleService.updateSoldCount()` 更新秒杀已售数量
- 但核销时 `pickupService.completePickup()` 对所有商品都扣减 `products.stock`
- 导致秒杀商品库存被双重扣减

**修复前测试结果**:
```
主库存变化: 91 → 90 (被错误扣减!)
秒杀已售变化: 1 → 1
```

**修复后测试结果**:
```
主库存变化: 88 → 88 (正确，未变化)
秒杀已售变化: 1 → 1
```

**修复方案**:
在 `pickupService.ts` 的库存扣减循环中添加判断：
```typescript
if (item.isFlashSale || item.snapshotCostPrice === null) {
  console.log(`[pickupService] 秒杀商品跳过库存扣减...`);
  await tx.product.update({
    where: { id: item.productId },
    data: { salesCount: { increment: item.quantity } },
  });
  continue;
}
```

**Git提交**: `5d9ee85b` - fix(P0): 修复秒杀商品核销时错误扣减主库存的BUG

### BUG-2: 砍价商品使用独立库存时核销错误扣减主库存 (P1)

| 属性 | 值 |
|------|-----|
| 严重度 | P1 (重要) |
| 状态 | **已修复，待实际业务验证** |
| 影响范围 | 使用独立库存的砍价商品 |

**问题描述**:
- 砍价可配置使用独立库存 `bargain_config_items.bargain_stock` 或主库存
- 砍价下单时，如使用独立库存则更新 `sold_count`，不扣减主库存
- 但核销时不知道是否使用独立库存，统一扣减主库存
- 导致使用独立库存的砍价商品库存被双重扣减

**修复方案**:
1. 在 `bargainOrderService.ts` 创建预约商品时设置 `isBargain: true` 和 `bargainId`
2. 在 `pickupService.ts` 核销时检查砍价商品是否使用独立库存，是则跳过主库存扣减

```typescript
if (item.isBargain && item.bargainId) {
  const bargain = await tx.bargain.findUnique({ ... });
  const bargainConfigItem = await tx.bargainConfigItem.findFirst({ ... });
  if (bargainConfigItem && bargainConfigItem.bargainStock > 0) {
    console.log(`[pickupService] 砍价商品(独立库存)跳过主库存扣减...`);
    continue;
  }
}
```

**Git提交**: `3e19d8e3` - fix(P1): 修复砍价商品使用独立库存时核销错误扣减主库存的BUG

**测试说明**: 当前系统中没有可核销状态的砍价订单，无法直接实测。修复已部署，待实际业务产生数据后验证。
